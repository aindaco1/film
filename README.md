# Film

Film is a static-first production workspace for solo filmmakers and small teams. It is being built as a lightweight app shell with Cloudflare Worker APIs, SQLite/D1-compatible schema, offline-first browser behavior, encrypted-backup-ready data boundaries, and provider integrations that start in dry-run mode.

The first slice includes:

- A static TypeScript PWA under `apps/web`
- A raw Cloudflare Worker API under `apps/worker`
- Shared schema, seed data, Dust Wave fixture data, and backup helpers under `packages/schema`
- Encrypted browser backup helpers under `packages/backup`
- Notion export importer helpers and normalized core/planning import contracts under `packages/importers`
- Local deterministic Fountain/Final Draft screenplay parsing with a revisioned breakdown, review workspace, occurrence tracking, duplicate-element cleanup, and filtered element-list handoffs
- Local versioned main/second-unit stripboards with atomic multi-strip moves, source-range scene splitting, cast/location availability, cross-unit cast collision checks, editable Travel/Hold DOOD annotations, explicit micro-budget scenario comparison, and transparent schedule-derived cost estimates
- Editable local call sheets generated from stable schedule-day scene snapshots, with explicit draft schedule sync, reviewed cast calls, logistics, safety notes, final/reopen state, and Markdown handoff
- Local daily production reports with scene outcomes, actual timing/count summaries, operational notes, and Markdown plus formula-safe CSV handoffs
- Provider dry-run contracts under `packages/providers`
- D1/SQLite-compatible migrations under `migrations`
- Local create flows for typed film projects, tasks, Markdown documents, people, equipment, and expenses with stable row IDs and queued operation metadata
- Authenticated canonical workspace hydration with queued-local reconciliation, canonical task transitions, and stale-checked Markdown body persistence
- Architecture, security, testing, and ADR notes under `docs`

## Local Development

```bash
npm install
npm run dev
```

Open the Vite URL printed by the command. The app works without production credentials.

The default command starts both the Vite app and the local Wrangler Worker so protected dry-run workflows can be tested. To run only one side:

```bash
npm run dev:web
npm run dev:worker
```

`apps/worker/wrangler.toml` is configured with the MVP Cloudflare resources: D1 `film`, KV `SESSIONS`, R2 buckets `film-backups` and `film-attachments`, non-secret Stripe summary adapter defaults for the Dust Wave Pool/Store Workers, the `https://api.film.dustwave.xyz` Worker custom domain, and live invite delivery gates. `apps/web/wrangler.toml` deploys the static app as the `film-web` Worker at `https://film.dustwave.xyz`. Migrations have been applied locally and remotely, `workers_dev` is disabled, and credentialed CORS origins are explicit through `ALLOWED_ORIGINS`. Run `npm run check:deploy -- --wrangler-secrets` or `npm run check:deploy:strict -- --wrangler-secrets` to verify production readiness without printing secret values. See `docs/DEPLOYMENT.md` for the non-secret Worker environment template and production handoff.

## Verification

```bash
npm run build
npm run test
npm run test:security
npm run test:migrations
npm run test:browser
npm run accept:screenplay -- /absolute/path/to/screenplay.fdx
npm run smoke:worker
npm run smoke:browser:worker
npm run smoke:providers:live
npm run smoke:auth:production
npm run smoke:local:worker
npm run check:companions
npm run check:deploy
npm run report:production-traffic
npm run smoke
```

`npm run smoke:worker` is opt-in for local/staging Worker verification. It skips when no origin is configured; run it against Wrangler or staging with `FILM_WORKER_SMOKE_ORIGIN=http://127.0.0.1:8787 npm run smoke:worker`.

`npm run smoke:browser:worker` is also opt-in. It drives the browser UI against a configured Worker origin, including signed auth, provider dry-runs, protected record and profile mutation apply paths, encrypted backup export, and restore preview; run it with `FILM_WORKER_SMOKE_ORIGIN=http://127.0.0.1:8787 npm run smoke:browser:worker`.

`npm run smoke:providers:live` is an opt-in local/staging provider-adapter smoke. It keeps Meta Insights and Telnyx SMS behind their disabled production gates and does not grant Google or Meta account consent; it calls Stripe Pool/Store summary adapters only with `FILM_LIVE_PROVIDER_SMOKE_ALLOW_STRIPE=1`, and it sends a Resend invite only with `FILM_LIVE_PROVIDER_SMOKE_SEND_INVITE=1` plus `FILM_LIVE_PROVIDER_SMOKE_INVITE_EMAIL`. Provider requests default to a 90s timeout for cold summary scans; override it with `FILM_LIVE_PROVIDER_SMOKE_TIMEOUT_MS` or `--timeout-ms`.

`npm run smoke:auth:production -- --allow-send --require` is the production-only auth probe. It sends one approved owner magic link, locates only the newly created matching Resend message, requires delivery, verifies the member session, logs out, and confirms revocation without printing recipient, message, token, cookie, CSRF, or secret values. It reads approved local operator values from environment variables or the ignored Pool `.dev.vars`; do not run it in CI or without approving the email send.

For local verification, `npm run smoke:local:worker` applies local D1 migrations, starts Wrangler at `http://127.0.0.1:8787`, verifies real-D1 member-status, collaboration, core restore proof-chain, and attachment restore proof-chain transactions, provisions an isolated D1 owner for the browser flow, runs `smoke:worker`, `smoke:browser:worker`, and `smoke:providers:live`, removes all probe identities, then shuts the Worker down.

`npm run report:production-traffic` reads Cloudflare analytics and active KV rate-limit windows using ignored operator credentials, then prints aggregate request/error/subrequest and per-bucket maximum counts only. It does not print account IDs, namespace IDs, credentials, or identity hashes.

Provider capability preflights default to dry-run. A separate protected runtime-readiness manifest reports Pool, Store, and Stripe as live only through summary-only adapters with canonical project mappings; those three gates are currently disabled because Big Sword has no companion refs. Resend reports live only for member magic links and gated invitations; Google reports live only when its encrypted OAuth gate is fully configured; Meta reports live only when its encrypted read-only OAuth/Page/analytics gate is fully configured; and Telnyx SMS reports configured-but-disabled until carrier registration and controlled acceptance pass. Real credentials stay out of the browser. Meta deauthorization/data-deletion callbacks are Worker-owned, signed, replay-safe, and independent of the interactive OAuth gate. Resend invite-delivery webhooks use a Worker-owned Svix signature check, record only bounded delivery metadata when D1 is available, update the linked attempt's latest event status, and create hash-only suppression rows for bounced, complained, or suppressed events.

The app uses Worker-owned magic-link authentication. Local Wrangler development explicitly runs in `dry_run` mode and can return a development token for deterministic smoke tests. Production runs with `AUTH_MAGIC_LINK_MODE=live`: requests return a generic accepted response, but Resend sends a link only for an existing active D1 workspace member. Tokens are stored only as hashes, expire, are consumed once, and are bound to that member/workspace; verification and protected authorization fail closed if D1/KV state is unavailable or the session lacks workspace/member scope. The browser consumes `magicLinkToken` from the production URL and removes it from browser history. A verified session's CSRF token is retained in same-tab `sessionStorage`, checked against the no-CSRF session metadata endpoint after reload, and then used to hydrate the bounded canonical D1 workspace snapshot; it is not persisted to long-lived local storage or recovered into a new tab.

The Notion importer accepts an extracted Notion export folder or Notion ZIP, runs a Worker preflight over file metadata, then reads bounded Markdown and CSV content locally. It creates the local review model and, for a signed owner/producer with a selected canonical project, sends normalized tasks, documents, people, equipment, expenses, and planning rows to separate Worker-owned D1 commit routes. Both routes use deterministic IDs and create-only atomic batches: exact replays are idempotent, changed existing rows are previews, and no import overwrites canonical data. Raw source paths and Markdown bodies stay out of operation/audit metadata. A separate screenplay import parses bounded `.fountain` and `.fdx` files locally into a revisioned scene, production-element, and occurrence graph with stable IDs and human review state; `.gwx` remains metadata-only until its format contract is documented. Breakdown includes ephemeral local search across headings, source, synopsis, and active graph elements plus a compact manual-tag form for adding a missed cast, location, prop, sound, or other supported category to the selected scene. Manual tags share parser normalization, deduplicate by category/name, start confirmed, and immediately feed existing schedule/DOOD/resource derivations. The Elements header can copy up to 100 active elements visible under the current category filter and explicitly paste them into other scenes in the same revision; the transient ID-only selection clears on reload, and repeated paste reuses the same deduplicating occurrence mutation. The scene list can switch between screenplay order and the selected matching stripboard's day/strip order; split parts emit their source scene once, unassigned scenes follow scheduled scenes, and missing schedule references fall back to script order. The selected category also drives a whole-revision Element List from that same graph, with active source/review metadata, occurrence counts, unique scene uses, first occurrence, and an expandable scene/line position ledger. An existing active element can be applied to the selected scene through the same normalized, deduplicating occurrence mutation; occurrence links return directly to the source scene. A bounded local name matcher surfaces likely same-category duplicates using normalized equality, contained names, shared terms, and spelling distance. Film never auto-merges: the user chooses the canonical name, then one shared workspace transaction combines source-free occurrences, removes exact scene/line duplicates, relinks live availability/location/talent references, and leaves issued call-sheet cast snapshots unchanged. Each active Element List row can also move to another supported category without re-tagging scenes. Exact normalized destination collisions are clearly labeled and reuse the canonical merge transaction; incompatible live availability/location/talent links block the move, while historical call-sheet snapshots remain untouched. Local Markdown and formula-safe UTF-8 CSV handoffs include the source-free position metadata while excluding screenplay text and private/provider state. Search query text and copied-element selections are not persisted. Script text, element names, suggestions, and breakdown data stay in the IndexedDB workspace and encrypted backups, never Worker requests, operation payloads, D1, or model calls. When a single new draft is imported from the selected prior revision, Film deterministically carries matching occurrence review states and exposes an explicit revision review for unchanged, changed, added, and removed scenes. `Carry planning forward` creates idempotent draft copies of matching schedules, budget assumptions, and availability windows, then relinks matching shots, talent, and locations while leaving unresolved records on the prior revision. Existing schedules remain intact; final call sheets, sides, and production reports stay pinned to their original source. The metadata-only revision report omits screenplay text and private/provider state. Supported Notion attachments are staged as local IndexedDB blobs and can be explicitly stored in R2 after Worker verification. Stored attachments can be exported as a bounded, plan-bound ZIP package. During restore, the browser and Worker verify package/object hashes independently, then a separate owner/producer-only commit route writes each missing object with create-only R2 semantics after the durable restore preflight chain and exact confirmation phrase. Legacy `.filmbackup.json` previews remain readable.

The Schedule sidebar item opens a selected-project versioned stripboard over the local screenplay graph. Scenes can be assigned and reordered across dated main- or second-unit shoot days. Producers can transiently select up to 200 whole-scene or split-part strips and move them together through one atomic shared-schema transition; stale selections fail before any strip changes, and selection clears after the move, a schedule mutation, version change, or reload. A montage or long scene can be split at an explicit source-line boundary into local `A`/`B` strips, moved across days independently, and merged back into one unassigned source scene without altering screenplay text. Versions can be duplicated and locked, and cast/location availability produces deterministic blocking or warning conflicts plus a cast DOOD matrix. Work is derived from assigned scenes; unlocked schedules let a producer mark each remaining cast/day cell Off, Travel, or Hold and show separate totals. Those annotations follow duplicated day IDs, disappear with deleted days, map only through resolved revision identities, and enter the metadata-only stripboard export. Film blocks a cast member scheduled to both units on the same date; consecutive-day metrics are calculated per unit so concurrent units do not inflate the streak. Per-version micro-budget assumptions expose strip, location, cast, consecutive-day, and company-move constraints; side-by-side comparison reports observed metrics and neutral deltas without inventing page counts, duration, cost, or a recommended winner. An optional schedule budget scenario starts every rate at zero and itemizes crew, cast work days, location days, equipment, company moves, meals, and contingency in integer cents. It is an estimate only: Film does not infer union rates, fringes, payroll taxes, or labor compliance, and the Expenses workspace remains the planned/actual ledger. Schedule and estimate state stay in IndexedDB and encrypted backups. Unit identity and split-range snapshots flow into call sheets, sides, reports, resource use, and local handoff exports. `Export stripboard` downloads metadata-only JSON without screenplay source text, while `Export packet` downloads the existing Markdown project packet. Project phase, call-sheet, and task summaries remain in Overview rather than being repeated here; no parallel calendar store or live Google Calendar dependency is added.

The Shots sidebar item stores scene-linked shot decisions without copying screenplay or schedule data. Each local record keeps in-scene order, shot number, description, planned/ready/captured/omitted state, framing, angle, movement, lens, camera/support, frame rate, setup group and estimate, sound/lighting/general notes, and references to existing project documents. Scene headings, schedule days, and generated call-sheet use are derived from the linked breakdown and production graph. Reorder controls affect only shots in the same scene. Local Markdown and formula-safe UTF-8 CSV exports include the current scene filter and derived production use while omitting screenplay source text, contacts, provider/private state, raw attachment bytes, and raw import paths. Shot records stay in IndexedDB and encrypted backups and do not call the Worker, D1, providers, or models.

The Call Sheets sidebar item opens a selected-project call-sheet workspace that can generate a local draft from any schedule day with assigned strips. Removed requirements leave the draft and newly required cast starts at the general call time. Final sheets are immutable until reopened, so issued sides/reports remain pinned unless the operator deliberately reopens and syncs their source sheet. Crew, gear, and attachments continue to reference existing project data instead of being copied.
