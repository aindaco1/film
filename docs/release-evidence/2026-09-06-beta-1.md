# Film 0.1.0-beta.1

Date: 2026-09-06. Controlled beta, not general-user provider approval. Deployment is verified below; the GitHub prerelease must separately identify its tested commit and successful CI run before publication.

## Included Work

- System-default light/dark appearance, high-contrast neutral tokens, contextual editing, bounded inspector navigation, shared creation controls, and an isolated 12-project demo portfolio.
- Production-derived project summaries, truthful empty states, shared resource and daily-document rendering, deferred backup/integration screens, offline recovery, and measured startup bundle budgets.
- The separately accepted Telnyx send/STOP/HELP/START lifecycle and Facebook-only Meta integration. Their original live evidence remains in the linked provider ledgers; this release does not send another SMS or enable Meta.
- One Google scope/capability and manifest contract shared by the planner, Worker, and browser. Folder reads deny redirects and reject malformed pagination instead of reporting false completion.
- Google reconnect recovery and guarded token refresh: disabled mode blocks stored tokens, and a refresh cannot overwrite a replaced connection or proceed after a concurrent disconnect. A stale failed refresh cannot invalidate the replacement connection.
- An unexposed selected-file metadata adapter and [scope evaluation](../google-selected-file-evaluation.md). It is not a live Picker implementation, new endpoint, permission change, or browser token route.
- GitHub CI now includes the existing real-local-D1 workflow suite and retains the tested static build as a SHA-named artifact.
- A fresh canonical workspace now keeps the existing shell, session controls, project creation, recovery, and integrations instead of replacing the application with a dead-end empty message. Desktop and mobile navigation share one project-availability guard; no placeholder project is invented.

## Scope and Remaining Acceptance

Meta's Dust Wave portfolio is assigned to Film, but its identity-verification form now asks for a masked representative who does not clearly match the authorized operator. No identity document or final verification was submitted. The operator must confirm the correct record/representative. Business/access verification, reviewer access/recording, App Review, and Instagram acceptance remain open.

Google's previously accepted owner-only metadata connection remains unchanged. The selected-file evaluation identifies a real tradeoff: non-sensitive `drive.file` is write-capable, and Picker requires an access token in the browser. Neither change is authorized or enabled. Public Google approval, Docs/Calendar acceptance, and non-empty live pagination are not claimed.

Broad real-team and manual assistive-technology acceptance remain separate from the automated 54-flow catalog. The main browser controller is still oversized; extraction of real domain boundaries and bundle budgets improve maintainability but do not eliminate that debt.
