# Film UX and Product Alignment Review

Date: September 5, 2026. Scope: local application, all operational workspaces, inspector workflows, public legal pages, appearance, keyboard behavior, responsive layout, and the documented product goals. No production configuration or provider permissions were changed.

Follow-up: the [demo and summary review](2026-09-05-demo-and-summary-review.md) addresses the template-era dashboard gap, adds an isolated varied portfolio, and records newer verification. Results below remain the historical evidence for this appearance pass.

## Conclusion

Film's local production chain is substantially implemented, and its framework-light/private-by-default direction is intact. The interface needed a shared appearance foundation and several concrete interaction fixes. Those changes are implemented in this review. This is a locally tested MVP candidate, not evidence that every provider or real-team workflow is production accepted.

The most important remaining product work is to replace template-era overview metadata with trustworthy production-derived summaries, simplify advanced collaboration language through real-team testing, and complete already documented provider acceptance gates. Adding another layer of features is not the next priority.

## Method and Boundaries

- Read `PRODUCT_GOALS.md`, `UI_SURFACE_OWNERSHIP.md`, `USER_FLOWS.md`, `ARCHITECTURE.md`, the existing acceptance records, renderers, shared contracts, and browser regression flows.
- Captured the unmodified interface before editing, then inspected rendered screenshots and real interactions rather than relying on source labels alone.
- Audited 17 workspaces and seven inspector views in Light and Dark at 1440x1000, 1280x900, 1024x900, and 390x844. Repeated the matrix with populated production fixtures and signed-in inspector state.
- Exercised expanded forms, project creation, keyboard navigation, system appearance changes, persistence, cross-tab updates, legal pages, and compiled offline reload. Existing regression flows cover the linked production chain and protected operations through mocked Worker responses.
- Used the executable 52-flow catalog as the flow source of truth. This report does not create a second flow inventory.
- The original Desktop plan file referenced in the task history was no longer at that path. Alignment was evaluated against the maintained product ledger, architecture, ADR-backed code, and current flow inventory instead.
- This pass did not conduct observed sessions with real crew members, native VoiceOver acceptance, live OAuth consent, live messaging, destructive production restore, or production deployment. Automated accessibility checks are not WCAG certification.

The review applies visibility of system status, recognition rather than recall, consistency, error prevention, and restrained information density from the [Nielsen Norman Group usability heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/). Contrast and keyboard checks are grounded in [WCAG 2.2](https://www.w3.org/TR/WCAG22/) and its [minimum text contrast guidance](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum).

## Implemented Findings

| Priority | Observed problem | Change and regression protection |
| --- | --- | --- |
| High | Fixed dark colors and component-specific RGB values prevented a coherent light mode. Several CSS variables were referenced but never defined. | One semantic neutral palette in `public/theme.css`. No raw component/legal color literals or undefined theme tokens remain. Static contracts and rendered contrast checks protect this. |
| High | Native controls fell back to inconsistent gray browser styling. Focus treatment was incomplete, and some fields had placeholder-only styling. | Shared input/select/textarea/button defaults, readable placeholders, visible keyboard focus, and neutral hover/selection states. Component rules still own domain-specific layout. |
| High | The accessible-name helper overwrote actual field labels, potentially calling a production date an expiration date. | Preserve native labels and explicit ARIA names. Only unnamed controls receive fallback names. Browser tests use the resulting accessible labels. |
| High | Project creation looked modal but did not support Escape or native background inertness. | Use HTML `dialog.showModal()`, native modal behavior, Escape/cancel handling, outside-click dismissal, and explicit focus return. Keyboard tests ensure focus cannot enter background app controls. Browser chrome remains reachable. |
| High | Offline registration could be missed when IndexedDB initialization completed after `window.load`. The topbar advertised offline readiness regardless. | A small tested lifecycle module registers both before and after load. The topbar now says Local workspace. Compiled-browser tests verify actual offline reload separately. |
| High | The service worker intercepted and cached arbitrary GET responses, including possible private API responses. Missing resources could receive HTML instead of a proper failure. | Cache only public allowlisted same-origin assets, exclude credential/query/private/error cases, and return a network error for unavailable uncached assets. Tests cover these privacy and failure boundaries. |
| Medium | Four overview lists were compressed into narrow columns, hiding names and production details. | Use two columns at normal desktop content widths, four only when the content area can support them, and one on mobile. Wrap summary content instead of truncating it. Remove decorative panel shadows. |
| Medium | Projects overflowed at tablet widths; crowded production headers and status cells were difficult to scan. | Bound project-table scrolling, retain labeled tablet navigation, allow workspace/production headers to wrap, and give task-status controls sufficient width. The populated responsive audit catches content-dependent failures. |
| Medium | Call-sheet generation had a dead-end prerequisite message. | A direct Open Schedule recovery link reaches the existing canonical workflow. No duplicate scheduling form was added. |
| Medium | Navigation rerendered the app without placing keyboard focus at the destination. Selection states were represented visually only in several switchers. | Shared navigation handler focuses the workspace heading; a skip link bypasses chrome. Navigation uses `aria-current`; selected project and mode buttons expose `aria-pressed`. |
| Medium | Appearance changes could easily have been implemented through a full app rerender, losing pending edits. | One delegated appearance controller updates only root theme state and matching controls. It persists locally, responds to system and cross-tab changes, and preserves unsaved fields. |
| Low | A static Today label suggested a current position in the template phase timeline. | Removed the unsupported Today marker. The underlying legacy timeline limitation remains explicit below. |

## Appearance Contract

- System is the default; Light and Dark are explicit local overrides. Returning to System resumes live OS preference tracking.
- The palette is black, white, and neutral gray. A restrained red is reserved for errors/overdue or removed states, which also have textual labels. Ordinary phases and integrations do not introduce separate hue families.
- The preference is not project data and is not copied into backups, provider requests, or shared schemas.
- A small shared bootstrap runs before the app renders. The app and four legal pages use the same palette and preference controller. Legal content follows system colors even without JavaScript.
- Storage failures leave the current page usable with a session-only choice. Forced colors and reduced motion are respected.
- Primary and secondary text are tested at a minimum 4.5:1 across all standard surfaces. Full-shell axe checks include contrast failures, but do not replace manual accessibility acceptance.

The implementation uses the browser's [color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/color-scheme), [light-dark()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/color_value/light-dark), and [prefers-color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme) behavior. No theme library, framework, or runtime dependency was added. Modern supported browsers are required; legacy-browser fallback is not a new support commitment.

## Goal Alignment and Remaining Work

1. **Production-first, private local workflows: on track.** The linked screenplay-to-report chain is tested and uses shared graph references. No cloud AI or publishing workflow was introduced. Optional local/BYOK assistance remains intentionally deferred.
2. **Simple project-focused UX: improved, not fully accepted.** Routine work is in context, navigation has one responsive owner, and the inspector has one active workflow at a time. Advanced permission/change/restore flows still expose technical concepts and require a real producer/contributor rehearsal. Do not remove approval or stale-write protections merely to shorten them.
3. **Trustworthy dashboard data: incomplete.** Seed project timelines use fixed month labels; project progress and backup-policy labels are not a complete projection of the live production graph or a scheduler. The generated Call Sheets/Schedule/Reports workspaces are more authoritative. Replace these legacy summaries and distinguish sample data clearly before broad first-run beta.
4. **Portability and recovery: on track locally.** Exports, encrypted backups, preview and approval boundaries remain intact. The offline cache is now restricted to public assets. Offline access to a lazy feature still requires its assets to have been fetched; the compiled gate verifies the loaded app shell, not every never-opened feature.
5. **Framework-light and DRY: on track with a maintainability risk.** This pass adds no package dependencies. Theme tokens, preference handling, accessibility semantics, navigation, and browser audit logic have single owners. The main renderer remains roughly 18.8k lines and the production entry remains roughly 610 kB minified; these are existing structural/performance risks, not solved by neutral colors. Extract real domain renderers incrementally, not a generic UI framework.
6. **Provider MVP: still externally gated.** The product ledger records Meta App Review/owned-account acceptance, Google owner consent, Telnyx carrier approval/controlled acceptance, and absent Pool/Store resource mappings as open. Those live states were not rechecked in this UI pass. The user's choice to leave publishing to Social and defer nonexistent Big Sword Pool/Store resources remains intact.
7. **Real-world usability: pending.** Run a small production through import, breakdown correction, two shoot days, changes after a call sheet is issued, crew access, and an encrypted handoff/restore rehearsal. Measure confusion, task completion, and recovery, not just click counts. Include mobile and VoiceOver users before claiming broad accessibility acceptance.

## Regression Evidence

The standard gates are `npm run build`, `npm run typecheck:web`, `npm run test`, `npm run test:security`, `npm run test:migrations`, `npm run test:browser`, and `npm run test:offline`. The focused appearance gate is `npm run test:appearance`. Generated flow docs remain checked against the executable catalog.

Final local results:

- Full build and web typecheck passed. The existing large-entry warning remains: 609.53 kB minified, 121.98 kB gzip.
- All 607 script/unit tests passed: 45 script, 202 web, 277 Worker, and 83 shared-package tests.
- Full browser regression passed, including the production chain, imports, in-context editing, permission/restore flows with mocked Worker responses, and mobile navigation.
- Appearance coverage passed 384 workspace/inspector combinations: 24 surfaces x two themes x four widths x seed/populated datasets. Expanded forms, modal keyboard behavior, forced colors, preference failures, and legal pages are additional checks.
- The compiled offline check passed after the final build: shell reload, saved appearance, cached legal navigation, and exclusion of private API responses.
- Secret scanning and all 37 SQLite-compatible migrations passed. No production deployment or live-provider acceptance was performed.
